# 自动更新数据回退修复与恢复记录

## 已确认的原因

[每日任务 41156800567](https://github.com/WooJi0127/zhiwei/actions/runs/41156800567) 的实际日志显示：恢复 `kpop-db-40987859116`，导出 4,520 条发行、764 条生日和 95 条 MV，随后存为 `kpop-db-41156800567`。本地整理成果未进入这条缓存链。

通过一次只读备份任务取回本次真实云端数据库，zip SHA-256 为 `0add10fdf1a5b96bf09c843d43187c8ef7a6351801b55b322987edd84e8102b6`。取回后与 10 月 22 日仓库快照、10 月 30 日本地库逐字段比较；原库均保留，未直接用旧本地库覆盖网页。

## 采用的流程

SQLite 继续用于采集。`scripts/catalog/*.jsonl` 保存九张公开采集表的固定列，每行一个条目；`manifest.json` 保存格式、数量、SHA-256（统一 LF 换行后计算，兼容 Windows Git 自动换行）。排序和编码稳定，Git 只记录变化的条目，不再每天追加完整二进制数据库。账户与密钥禁止进入此快照。

日/周工作流共用 `zhiwei-public-catalog` 并发组，取得执行机会后检出最新 main，从正式快照重建数据库。缺失或损坏直接失败，旧 Actions cache 和 `data/kpop.db.gz` 不再作为自动运行来源。最新发行先采集，再补 MV。

导出前保护已知非空内容、应用人工修正，检查原始记录 ID 及网页主文件和全部年份切片。新增记录不能抵消旧记录丢失；生日、艺人、曲目和无明确下架证据的 MV 减少会阻止发布。十年窗口自然过期、明确范围过滤、同专辑去重、已确认下架和有证据的人工删除允许执行。

成功导出后同时保存正式快照，再分发网页并提交。提交前检查 main 是否被其他人更新，推送仍受 Git 非快进保护；冲突时保留旧网站，不盲目 rebase 过期数据。Git 历史是可追溯备份，不依赖缓存保留期。

## 合并规则和修正

`reconcile_catalog.py` 仅用于显式、离线三方恢复，不在日任务中运行。保留两边独有行，只有一边改动的字段取改动值，空响应不抹掉已有字段；两边相互冲突的真实内容必须人工审查。采集时间可取较新值。Coogie《HBK》的本地源生类型 `Single` 保留；云端的 `Album` 没有源生类型证据，不用曲目数量反推类型。

保留云端独有的 567 条原始发行中的 556 条。另 11 条恰为此前 [5ab4843](https://github.com/WooJi0127/zhiwei/commit/5ab48439c5af9a6ad51290d7ef00a9df2236a115) 已核实删除的 Minzy 误绑作品，继续排除。正确 Apple 艺人 ID 和这 11 条删除记录写入 `catalog-corrections.json`，附原因及来源，每轮重放；身份变化使错误艺人的抓取缓存失效。

合并时发布门禁拦住了 5 张专辑的曲目减少。原因是去重只区分「有无曲目」，可选中曲目更少的版本。现优先保留曲目更完整的同专辑记录，并用回归测试复现和验证。

## 日常操作

第一次在新电脑运行：`python scripts/catalog_state.py restore`。有未保存本地改动时会拒绝覆盖；确认采用正式版本可用 `restore --replace`，旧库先备份至 `.build-logs/catalog-backups/`。

手工纠错记录在 `scripts/catalog-corrections.json`（目标表/主键、字段或删除、原因、来源）；然后 `python scripts/build.py --export-only`、`python tools/sync.py`、网页测试并提交源码/正式快照/全部生成数据。不得只提交网页数据，不保存快照。

发布门禁报错时按具体 ID 核实；合理删除写入有来源的修正记录，再重新导出。不要删掉检查、修改数量阈值或重建空库绕过保护。

恢复旧正式版本时检出同一次成功提交的代码、快照与产物，先验证再重新发布。自动任务的 verify 模式以及修改流程代码后的 push 验证，均不会抓取或提交数据。

## 验证进度

50 项离线 Python 测试通过，含 23 项新增快照/发布保护/三方合并测试。网页冒烟全部断言通过，手机横竖屏、平板、电脑共五尺寸布局检查全部通过。

对真实旧云端数据库重放检查，成功阻止生日、发行、曲目等回退；完全无缓存的新数据库可从正式快照恢复全部表。正式项目生成数据与通过浏览器测试的隔离副本一致（仅生成时间不同）。

独立审查发现的 Windows Git 换行转换问题已修复，未发现其他已确认的 P1/P2 阻断项。审查中的独立单测受到沙箱限制，最终运行依据为主流程的正式目录测试。当前已有韩文艺人都有 Apple ID，自动归一不会改名；未来若发生已有艺人改名，严格主键保护会要求核实并记录迁移，不静默当作删除。

源码 whitespace 检查通过；ICS 保留 RFC 要求的 CRLF 及折行，使用专门日历测试校验，未为消除 diff 空白提示而破坏日历格式。云端验证与公网部署另以本次 Actions 结果及实际文件哈希验收。
