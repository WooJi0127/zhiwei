# 知未 · K-POP 回归日历

把「未来谁会回归」和「过去发过什么」收进一个页面。搜索、筛选、收藏、本命置顶，点进专辑看完整曲目。

纯本地运行，不做播放，也不放外链。

**Windows · Android · iOS · 网页版**，一套代码，数据一致。

## 关于「知未」这个名字和图标

图标是一个**倒转的时钟**：原本 1 的位置写着 11，原本 2 的位置写着 10，整圈数字左右镜像。

寓意是「时间倒着数」——回归是倒计时，发布是回溯。名字取「知晓未发生的事」。

## 功能

### 五个标签页

- **即将回归** — 未来的发行，按日期排，卡片带 D-N 倒计时
- **本月回归** — 只显示当月，顶部写「共 X 张 · 其中 Y 张还没发行」
- **全部发布** — 所有已收录的发行，可回溯，也是唯一带完整筛选栏的板块
- **我的收藏** — 点卡片右上角 ☆ 收藏
- **本命动态** — 本命的回归单独追踪

### 卡片

第一行是**专辑 / 单曲名**，第二行是**艺人名**。艺人名旁边是红爱心，点一下加本命，会弹出小爱心动画。

右上角 ☆ 是收藏，歌手旁 ❤ 是本命——两个是分开的：
- **收藏**：针对单张专辑，想看的时候翻出来
- **本命**：针对艺人，所有作品自动置顶高亮

### 专辑详情页

点卡片任意位置进入，内容有：

- 大封面、专辑名、艺人名
- 发行日期、曲目数、总时长、音乐风格
- 经纪公司、粉丝名、出道年、版权方
- **完整曲目列表**：序号 + 歌名 + 时长
- 点某一首歌，**向下展开**这首歌的详情（时长、曲序、风格、制作团队）
- 「更多该艺人的作品」横向推荐
- 底部标注**数据来源**（Apple Music / 网易云音乐 / kpopping 日程）

**没有跳转链接**。卡片和详情页都不放外部链接——数据来自多个源，
点进去跳到哪家都不合适，而且链接会过期。要听歌就自己打开音乐 App 搜。

### 五个板块，各自的时间控件不同

| 板块 | 时间控件 | 筛选栏 |
|---|---|---|
| **即将回归** | 只能选「未来 7 天」或「未来 30 天」 | 无 |
| **本月回归** | 固定为当月，显示「共 X 张 · 其中 Y 张还没发行」 | 无 |
| **全部发布** | 完整日历 + 全部快捷预设 | **有** |
| 我的收藏 / 本命动态 | 按艺人聚合，不分时间 | 无 |

**筛选、搜索、排序只在「全部发布」里出现**——前面两个板块就是给你一眼扫的，不该被控件干扰。

### 全部发布的时间筛选（日历）

点筛选栏的「📅」按钮唤出日历：

- 月历上**有发行的日期带小圆点**，一眼看出哪天热闹
- 点两个日期选定**任意区间**（比如 3 月 1 日到 4 月 15 日），可跨月
- **点标题「2026 年 10 月」**唤出年/月面板，直接跳到任意年月
- **整月 / 整年** 一键选中当前显示的整个月或整年
- 底部实时显示已选范围与天数，如「已选 2026-10-06 → 2026-10-21　共 16 天」
- 快捷按钮：未来 7/30/90 天、全部未来、过去 30 天、本月、过去 1 年、全部已发布、今年至今、去年

### 其他筛选（仅「全部发布」）

- **发行类型**：单曲 / 迷你专 EP / 正规专
- **艺人分类**：团体 / Solo / 女团 / 男团 / 混声团 / 女歌手 / 男歌手
- **经纪公司**：按母公司归并，只有十几个选项
- 排序（日期 近→远、艺人名）、只看收藏、只看本命

搜索支持团体名、歌手名、专辑名、公司、粉丝名，**中文和英文都能搜**。

### 关于男女分类的准确率

男女分类来自 kpopping 的四个名录页（女团 / 男团 / 女歌手 / 男歌手），
再用手写名单补一部分，混声团则认详情页上 kpopping 自己的 `co-ed group` 徽章。

218 个艺人里 **200 个能分出男女（92%）**，剩下 18 个是查不到资料的小众艺人——
它们会出现在「团体 / Solo」里，但不会误分到男女分类下。宁缺毋滥，不猜。

### 语言显示

艺人名按 **中文 > 英文 > 韩文** 的优先级显示。有通用中文名的（防弹少年团、东方神起、少女时代等）显示中文 + 英文小字，其余显示英文名。

数据里不会出现韩文——Apple Music 偶尔返回韩文艺人名，脚本会自动归一成英文。

---

### 公司筛选按母公司

经纪公司自动归并到母公司，筛选列表只有十几个，不会因为一堆子公司而找不到要追的团。

例如 `BIGHIT MUSIC`、`PLEDIS`、`ADOR`、`SOURCE MUSIC`、`KOZ`、`BELIFT LAB` 都归到 **HYBE**；
`Starship`、`IST`、`EDAM`、`High Up` 都归到 **Kakao Entertainment**。

想改归并规则，编辑 `scripts/names.py` 的 `AGENCY_PARENT`。

## 关于「制作团队」为什么是空的

作词 / 作曲 / 编曲名单，**目前拿不到**。我把能想到的源都测过一遍：

| 数据源 | 实测结果 |
|---|---|
| Apple Music / iTunes 公开接口 | 曲目、时长、风格都有，但**不含制作人员** |
| **Discogs** | 能用，且**有 credits 字段**，但 K-pop 专辑的 credits 实测**全部为 0 条**；而且按名字搜索会错配（搜「IVE REVIVE」匹配到牙买加雷鬼专辑）。为每张专辑 2 次请求 × 1328 张 ≈ 2 小时，收益为零 |
| MusicBrainz | 对老牌艺人有收录（TWICE 命中 955 条），但对**新专辑命中率 0/6**，四代团的迷你专基本没有 |
| Deezer API | 网络不通（502） |
| Wikipedia API | 网络不通（502） |
| Genius | 需要付费 token |
| Melon / Bugs | 需要爬虫 + 专辑 ID 映射 + 对抗反爬，且韩网直连不稳定 |
| QQ 音乐公开搜索接口 | `c.y.qq.com/soso/fcgi-bin/client_search_cp` 返回 200 但**结果恒为空**（连 IVE 都搜不到），接口已废弃 |

所以详情页的「制作团队」一栏写的是「暂未收录」，**没有编造数据**。

次要的损失是「风格」粒度：Apple Music 只给到 `K-Pop` 这一级。Discogs 能给到 `Dance-pop`、`Pop Rap` 这类，但如上所述成本太高，目前没接。

如果你愿意用稳定性换完整度，后续可以试着接 Melon 抓取——但那会明显增加更新失败的概率。

### 目前已有的数据覆盖

| 项目 | 覆盖率 |
|---|---|
| 专辑曲目 | 1600 张里 **1442 张有完整曲目**（90%） |
| 缺曲目的 | 主要是 kpopping 收录的**未来专辑**——还没发行，本来就没有曲目 |
| 艺人有团体/个人分类 | **83%** |
| 艺人有男女分类 | **92%** |
| 中文名 | 只收录有通用中文名的（20 个），其余用英文官方名 |

分来源看曲目覆盖：Apple Music 1144/1215，网易云 298/298，kpopping 0/114（未来专辑，正常）。

### 发行形态是怎么判定的

单曲 / 迷你专 EP / 正规专这三类，数据源给得都不干净：Apple Music 的标题带 `- Single` / `- EP` 后缀还算好认，
网易云则完全没有形态字段。所以统一交给 `parse_subtype` 按五档优先级猜：

1. 标题后缀（`XXX - Single` / `XXX - EP`）——最可靠
2. 序数专辑写法（`The 1st EP` / `2nd Mini Album` / `3rd Single Album`）
3. 裸关键词（`Mini Album` / `Single Album` / `EP` / `Single`）
4. 数据源自带的形态字段
5. **曲目数兜底**（1–2 首=单曲，3–7 首=EP，8 首以上=正规专）

第 5 档是接了网易云专辑详情之后才有的——之前网易云那 298 张因为没有曲目数，全被判成正规专。
规则一改，`step_retype` 会把库里所有条目重刷一遍，不会出现新旧数据分类不一致。

### 同一张专辑不会被重复收录

三个源会重复收录同一张专辑，而且写法各不相同：

| 差异 | 例子 |
|---|---|
| 标题写法 | `PAPARAZZI ARRIVE` vs `PAPARAZZI ARRIVE - The 1st EP` |
| 合作标注 | `B.B.B` vs `B.B.B (feat. A2O LTG)` |
| 日期 | Apple `2026-07-17` vs 网易云 `2026-07-16` |

所以去重分两步：先把标题归一（去 feat 标注、去 `- Single` / `- The 1st EP` 后缀），
再按艺人 + 标题分组，**组内日期相差 ±3 天的认作同一张**。

留哪一份按「有曲目 > 有曲目数 > Apple Music」排；
形态则优先采信**标题里带明确线索**的那份——不然会出现同一个 EP，
Apple 的裸标题靠曲目数猜成正规专、网易云的 `The 1st EP` 才是对的，两边打架。

目前合并掉约 258 条重复收录。

## 数据来源

| 来源 | 用途 |
|---|---|
| [kpopping.com](https://kpopping.com) | 未来回归日程（含封面、发行类型）、艺人的男女分类名录 |
| [Apple Music](https://music.apple.com) | 历史发行归档 + **专辑曲目**，主力源 |
| [网易云音乐](https://music.163.com) | 补 Apple Music 没上架的专辑，补曲目，以及**发现新团体** |
| [kpopcal.com](https://kpopcal.com) | 官方确认事件（CC BY 4.0） |

三个源各管一段，互不替代：

- **未来**只能靠 kpopping 的日程——Apple Music 拿不到还没发行的专辑
- **历史归档**靠 Apple Music，它的曲目数据最全
- **Apple Music 上根本没有的团**（比如只在中国市场发行的），靠网易云补

**追踪范围**：韩语专辑 / 迷你专 / 单曲，团体与个人都收，新团另标。
**排除**：OST、Remix、Instrumental、日语版 / 中文版等衍生发行。

想调整范围，改 `scripts/build.py` 里的 `EXCLUDE_PAT`。规则收紧后，
`step_purge_scope` 会把老数据里已经混进去的越界条目一并清掉，不会出现「规则改了但脏数据还在」。

### 新团体是怎么被发现的

这是最容易漏的一环。**Apple Music 只能给「已经知道名字的艺人」补数据，它自己不会告诉你今天出了个新团。**
kpopping 的日程又以韩国市场为主，只在中国发行的团它不收。

所以发现新团走三条路，按顺序：

1. **网易云新碟榜扫描**（`--full` 时跑）：翻韩国区新上架专辑，挑出艺人名字不在库里的，
   再用 `itunes_find_kpop` 回验一次「确实是 K-Pop 艺人」，通过了才入库。防止把中文名误判成新团。
2. **已确认名单**（`SEED_ARTISTS`，每次都跑）：手写名单，绕过所有发现逻辑直接补。
   目前是 `A2O LITE / A2O MAY / A2O SOUL`——它们就是在这一步才被收进来的。
   网易云的新碟榜翻了 900 张专辑也没找到它们。
3. **孤儿回填**：艺人名已经在库里、但一张专辑都没有的，会补抓一次。

发现某个团没收录，最快的办法是把它加进 `scripts/build.py` 的 `SEED_ARTISTS`，跑一次 `update.bat` 就有了。

## 常见问题

**打开是空白 / 没数据？**
双击 `update.bat` 跑一次，确认 `data/data.js` 生成成功，再刷新。

**封面图不显示？**
封面来自 kpopping 与 Apple Music 的 CDN，需要联网。断网时显示占位图标。

**更新失败？**
看 `update.log`。脚本设计成任一数据源挂掉都不影响整体，会保留上次成果。

**数据从什么时候开始？**
目前最早到 **2024-10-18**，往前没有。这是 `scripts/build.py` 里 `HISTORY_DAYS = 730`（两年）的窗口限制，
不是数据源拿不到——Apple Music 能一直往回翻。改大这个值再跑一次 `--full` 就能补更早的，
只是耗时会长很多。**历史回溯这块还没做**，先把其他功能收尾。

**为什么「全部发布」只显示了 800 多张，角标却写着 1565？**
首次切到「全部发布」默认按**过去 1 年**展示，不然一上来铺 1500 多张卡没法看。
角标显示的是全部存量。点筛选栏的 📅 → 「全部已发布」就能看完整归档。

**命令行高级用法**

```bash
python scripts\build.py            # 日常增量（约 3 分钟）
python scripts\build.py --full     # 全量重抓（约 25 分钟，会重新拉曲目 + 扫网易云新碟榜）
python scripts\build.py --quick    # 只抓日程，跳过 Apple Music 和补曲目（几秒）
python scripts\build.py --limit 5  # 只处理前 5 个艺人，用于调试
python scripts\build.py --export-only  # 不联网，只用现有数据库重新生成 data.js
```

`--export-only` 用来在改了展示/归类规则之后立刻看到效果，不用等一轮抓取。

**备份收藏和本命**
收藏存在浏览器的 localStorage 里，不上传。清缓存或换浏览器会丢。换电脑前记得重新标记。
