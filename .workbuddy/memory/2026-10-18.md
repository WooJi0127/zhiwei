## 网站自动更新（方案②）：GitHub Actions 自动抓数据 + Cloudflare Git 自动部署

### 背景
- 网页版已上线可访问：`https://zhiwei-kpop.wooji.workers.dev/`
  （用户把 worker 名定为 `zhiwei-kpop`，账号子域 `wooji`）
- 之前的「数据未生成」问题已解决：重传 `site/app/` 全部内容（含 `data/data.js`）后统计数字正常。
- 关键认知澄清：**访客不需要跑任何脚本**，那句提示只面向站长。

### 本轮创建的文件
- **`.gitignore`**（项目此前没有，风险很高）：
  必须忽略 `desktop/`（821M）、`mobile/`（96M）、`site/downloads/`（160M）里的
  `node_modules` / `dist` / `build` / `*.exe` / `*.apk`，
  以及 **`*.jks` + `keystore.properties`**（APK 签名密钥与密码，敏感，禁止提交）。
- **`.github/workflows/daily-data.yml`**：
  - 触发：`schedule` cron `0 1 * * *`（UTC，= 北京 09:00 每日一次）+ `workflow_dispatch`（手动）
  - `permissions: contents: write`（允许回推数据）
  - `actions/cache` 持久化 `kpop.db` → 保留历史、增量抓取（~3 分钟；无缓存则全量 ~25 分钟）
  - 核心一步：`python tools/daily_update.py`（= `scripts/build.py` 抓取入库导出 + `tools/sync.py` 分发各端）
  - 有变更才 `git add -A && commit && pull --rebase && push`，无变化跳过
  - push 后由 Cloudflare 的 Git 集成自动重新部署网站

### 环境核查结论
- **依赖**：`scripts/`（build/sources/names）与 `tools/sync.py` **全部只用 Python 标准库**，零第三方包 → CI 端无需 pip install。
- 本机：Python 3.13.14、git 2.55.0 可用；项目**尚未** `git init`。
- 本机 `curl workers.dev` 连不通（状态码 000）→ **国内访问 workers.dev 不稳定**，
  长期方案仍是国内托管（OSS/COS）+ 域名 ICP 备案。
- 另建了隔离 venv `~/.workbuddy/binaries/python/envs/default` 并装了 pyyaml（用于校验 YAML）。
