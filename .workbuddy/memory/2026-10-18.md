### 本轮创建的文件
- **`.gitignore`**（项目此前没有，风险很高）：
  必须忽略 `desktop/`（821M）、`mobile/`（96M）、`site/downloads/`（160M）里的
  `node_modules` / `dist` / `build` / `*.exe` / `*.apk`，
  以及 **`*.jks` + `keystore.properties`**（APK 签名密钥与密码，敏感，禁止提交）。
- **`.github/workflows/daily-data.yml`**：
  - 触发：`schedule` cron `0 1 * * *`（UTC，= 北京 09:00 每日一次）+ `workflow_dispatch`（手动）
  - `permissions: contents: write`（允许回推数据）
  - `actions/cache` 持久化 `kpop.db` → 保留历史、增量抓取（~3 分钟；无缓存则全量 ~25 分钟）
  - 核心一步：`python tools/daily_update.py`（= `scripts/build.py` 抓取入库导出 + `tools/sync.py` 分发各端）
  - 有变更才 `git add -A && commit && pull --rebase && push`，无变化跳过
  - push 后由 Cloudflare 的 Git 集成自动重新部署网站

### 环境核查结论
- **依赖**：`scripts/`（build/sources/names）与 `tools/sync.py` **全部只用 Python 标准库**，零第三方包 → CI 端无需 pip install。
- 本机：Python 3.13.14、git 2.55.0 可用；项目**尚未** `git init`。
- 本机 `curl workers.dev` 连不通（状态码 000）→ **国内访问 workers.dev 不稳定**，
  长期方案仍是国内托管（OSS/COS）+ 域名 ICP 备案。
- 另建了隔离 venv `~/.workbuddy/binaries/python/envs/default` 并装了 pyyaml（用于校验 YAML）。

### 推送 GitHub 时踩的坑
1. `git commit` 报 `Author identity unknown` → 需先设 `user.name` / `user.email`。
2. `git remote add origin` 报 `already exists` → 因为之前把**示例占位地址**
   `https://github.com/你的用户名/kpop.git` 原样粘进去执行过。
   → 正解是 `git remote set-url origin <真实地址>`，不是 `remote add`。
3. **真实仓库**：`https://github.com/WooJi0127/zhiwei.git`（用户名 WooJi0127，仓库 zhiwei），
   分支 `main`，首个提交 `b6b5690 init: 知未 K-POP 回归日历`，共 130 个文件。
4. 教训：给用户的命令里**示例地址要用醒目占位符并明确标注「请替换」**，
   否则新手会原样复制执行。

## Workers Builds（Cloudflare Git 构建）实测

- 用户按早前提示删掉了手动上传的旧 Worker → 改走「Import a repository」新建，
  项目名仍为 `zhiwei-kpop`，网址不变 `zhiwei-kpop.wooji.workers.dev`，仓库 `WooJi0127/zhiwei`。
- **新版 Workers Git 构建必须在仓库根放 `wrangler.jsonc`**：
  `name` 必须与面板 Worker 名一字不差（否则 name mismatch 构建失败），
  `assets.directory` 指向 `./site/app`；Build command 留空，Deploy command 默认 `npx wrangler deploy`，
  API token 自动创建，构建变量留空。经典 Pages 的「Build output directory」字段已不存在。
- **坑：新版 wrangler 部署不再自动开启 workers.dev 域名** → 面板显示 `No URLs enabled`、
  Domains & Routes 里 workers.dev = Disabled。
  修复 = 面板手动 Enable + `wrangler.jsonc` 加 `"workers_dev": true`（提交 eeebe1a）。
- 本机直连 GitHub 间歇失败（schannel 断连 / Empty reply / CONNECT 502），重试即可通过；
  用户 PowerShell 环境推送正常。
